# 知识库与知识图谱：研究与改版说明

## 查阅的资料

1. [Neo4j · How to build a knowledge graph in 7 steps](https://neo4j.com/blog/knowledge-graph/how-to-build-knowledge-graph/)：先明确使用场景，再定义实体、关系和属性；清洗数据、验证关联、持续维护。小型项目不必先引入复杂本体或图数据库。
2. [yFiles · Guide to Creating Knowledge Graph Visualizations](https://www.yfiles.com/resources/how-to/guide-to-visualizing-knowledge-graphs)：布局应匹配任务；分类结构用层次布局，主题探索用网络布局；颜色和形状表达语义；通过搜索、筛选、邻域展开和按需详情避免 hairball。
3. [Stanford CS520 · How do users interact with a knowledge graph?](https://web.stanford.edu/class/cs520/2020/notes/How_Do_Users_Interact_With_a_Knowledge_Graph.html)：概览 → 动态查询与缩放 → 按需详情。不要把所有信息同时塞进画布；图形与文本详情应互相补充。
4. [W3C · PROV Overview](https://www.w3.org/TR/prov-overview/)：来源信息用于评估数据质量和可信度，应能追溯实体、活动和责任主体。
5. [React Flow documentation](https://reactflow.dev/api-reference/react-flow)：采用 MIT 许可的 React Flow 实现可拖拽节点、平移缩放、键盘焦点和小地图；保留项目署名。

## 原页面的主要问题

- 重复标题、大段介绍和最近新增卡片占据首屏，真正的图谱被推到下方。
- Canvas 中知识标题默认不可见，必须悬停；缺少键盘节点操作。
- 点击节点跳到下方卡片，探索上下文丢失。
- 装饰性中心节点、流动粒子和大量交叉线不表达可核查的事实。
- 分类、关键词、卡片和图谱的筛选状态分散；关联数量与实际可见图谱不一致。
- 编辑表单插入长页面，保存提示远离操作位置。

## 知识域分层（中心图谱 → 子库）

- 知识网分为四个大知识库：**中心**（通用事实与团队约定）、**前端**（界面与交付）、**后端**（数据与口径）、**创作**（品牌与文案）。
- 中心图谱首屏只显示这 4 个知识域节点（含条目数与一句话定位），点击节点或右侧面板进入对应子库；子库内点击中心的星座核，或使用面包屑「← 中心图谱」返回。
- 子库默认使用**星座轨道**布局：星座核居中、分类在内环、知识在外环，轨道虚线与缓慢旋转的扫描光带表达“星系”隐喻；也可切换回关联网络与分类结构。
- 每条知识可通过 `library` 字段显式归属知识域，未填写时按分类推导（分类名等于知识域名时优先），因此旧数据无需迁移。
- 顶部知识域切换条支持随时跳转，卡片视图同样按知识域过滤；搜索结果会自动跳到该知识所在的知识域。

## 本次实现

- 紧凑页头、真实统计、来源标签；图谱和卡片共享搜索、分类、关键词筛选。
- 图谱 + 原位详情；概览、完整原文、引用代码分开；关联连线显示依据。
- 关联网络 / 分类结构两种布局；关键词节点显隐；关系类型筛选；一跳 / 两跳邻域。
- 标题常显、语义配色、节点拖动、缩放按钮、小地图、全屏、键盘操作。普通滚轮保留页面滚动，Ctrl + 滚轮缩放。
- 默认最多 40 条知识，手动加载更多；共享关键词采用最大权重生成森林减少稠密交叉，完整证据保留在关系数据中。窄屏默认聚焦当前知识的一跳邻域，避免全图缩放到不可读；小地图保留全局上下文，复位按钮可适应全图。
- 关键词 NFKC 归一化与大小写合并；明确关系支持参考 / 依赖，校验目标、去重、禁止自关联；删除时清理悬空关系。
- 来源 URL、创建 / 更新时间、来源类型；未提供来源时明确显示未经外部核验。
- 原生 dialog 焦点管理；保存错误原位显示；删除确认；JSON 导出备份。
- 保持原有 localStorage 数据键，旧条目无需迁移；没有更改模型、工作台、历史等逻辑。

## 诚实的边界

这是轻量、可追溯的知识关系视图，不是完整 GraphRAG，也不包含 AI 实体抽取、自动事实验证或语义向量检索。共享关键词只表示主题相似，不等于引用事实。提示词构建仍使用原来的相关性匹配，最多 3 条、约 2400 字。数据保存在当前浏览器，不跨设备同步；外部来源需要人工核查。

## 构建与测试

本项目直接用 `npm run build` 生成单文件 `dist/index.html`。`vite.config.js` 使用 `resolve.dedupe` 保证应用与图谱渲染器 `@xyflow/react` 共用一份 React，避免嵌套部署时出现重复 React Hook 错误。

图谱单元测试：`npm test`（包含 `tests/knowledge-graph.test.ts`）。
浏览器交互测试：启动开发服务器并安装 `playwright` 后运行 `APP_URL=http://127.0.0.1:5173 node tests/knowledge-web.mjs`。
